# User Story: Aggregate Frame-Level Validation Results in Cross-Validation

## Overview
Enhance `run_cv.py` to aggregate frame-level validation results across all cross-validation folds and seeds, creating separate aggregate CSV files for each landmark set.

## User Intent
When running cross-validation experiments with `run_cv.py`, I want to automatically collect and aggregate the frame-level validation output (generated by `deeplabcut.evaluate_network()`) into consolidated CSV files - one per landmark set - that combine results from all folds and seeds for downstream analysis.

## Background
- User Story 01 introduced the `save_frame_level_results` flag in `deeplabcut.evaluate_network()` which generates a CSV file named `{DLCscorer}-frame-level-results.csv` containing ground truth positions, predictions, and confidence scores for each test frame
- `run_cv.py` currently evaluates multiple landmark sets (e.g., 'all', 'truncated') for each fold/seed combination
- Each evaluation creates a separate frame-level CSV in the evaluation folder
- These individual CSVs need to be aggregated for analysis across the entire cross-validation experiment

## Requirements

### Primary Goal
After each call to `deeplabcut.evaluate_network()` in `run_cv.py`, parse the newly generated frame-level CSV and incrementally append its rows to a landmark-set-specific aggregate CSV file.

### Functional Requirements

1. **Flag to Enable Frame-Level Output**
   - Add a constant `SAVE_FRAME_LEVEL_RESULTS` at the top of `run_cv.py` (alongside other constants like `N_EPOCHS`, `N_FOLDS`, etc.)
   - When enabled (`True`), pass `save_frame_level_results=True` to `deeplabcut.evaluate_network()`
   - Default value should be `False` to maintain backward compatibility and avoid generating large files unless explicitly requested

2. **Parse Frame-Level CSV After Each Evaluation**
   - After each `deeplabcut.evaluate_network()` call completes, locate the generated `*-frame-level-results.csv` file
   - Read the CSV into a pandas DataFrame
   - Add metadata columns: `fold`, `seed`, `experiment_id`, `landmark_set_name`, `shuffle_num`

3. **Incremental Aggregation by Landmark Set**
   - Maintain separate aggregate CSV files for each landmark set (e.g., `cv_frame_level_results_{experiment_id}_all.csv`, `cv_frame_level_results_{experiment_id}_truncated.csv`)
   - After parsing each frame-level CSV, append its rows to the appropriate landmark-set-specific aggregate file
   - Use incremental saving pattern similar to `save_results_incrementally()` function

4. **File Naming Convention**
   - Aggregate files: `cv_frame_level_results_{experiment_id}_{landmark_set_name}.csv`
   - Store in the same directory as the main CV results file (`cv_results_{experiment_id}.csv`)

5. **Metadata Columns**
   - Add the following columns to each row in the aggregate CSV:
     - `fold`: Fold index (0-based)
     - `seed`: Seed index (0-based)
     - `experiment_id`: Experiment identifier string
     - `landmark_set_name`: Name of the landmark set (e.g., 'all', 'truncated')
     - `shuffle_num`: Shuffle number used for this fold/seed

### Non-Functional Requirements

1. **Performance**: Incremental appending should be efficient (avoid re-reading entire aggregate file each time)
2. **Robustness**: Handle missing frame-level CSV files gracefully (log warning, continue execution)
3. **Consistency**: Use the same incremental saving pattern as existing `save_results_incrementally()` function

## Expected Workflow

```python
# At top of run_cv.py (with other constants):
SAVE_FRAME_LEVEL_RESULTS = False  # Set to True to aggregate frame-level validation results

# In run_single_fold():
for landmark_set_name, landmark_set in landmark_sets.items():
    # 1. Call evaluate_network with save_frame_level_results flag
    deeplabcut.evaluate_network(
        config_path,
        Shuffles=[shuffle_num],
        plotting=False,
        comparisonbodyparts=landmark_set,
        save_frame_level_results=SAVE_FRAME_LEVEL_RESULTS  # Use constant
    )
    
    # 2. Locate the frame-level CSV
    frame_level_csv = evaluation_folder / f"{DLCscorer}-frame-level-results.csv"
    
    # 3. Parse and add metadata
    df_frame_level = pd.read_csv(frame_level_csv)
    df_frame_level['fold'] = fold_idx
    df_frame_level['seed'] = seed_idx
    df_frame_level['experiment_id'] = experiment_id
    df_frame_level['landmark_set_name'] = landmark_set_name
    df_frame_level['shuffle_num'] = shuffle_num
    
    # 4. Append to landmark-set-specific aggregate file (only if flag is enabled)
    if SAVE_FRAME_LEVEL_RESULTS:
        aggregate_file = f'cv_frame_level_results_{experiment_id}_{landmark_set_name}.csv'
        append_frame_level_results_incrementally(df_frame_level, aggregate_file)
```

## Acceptance Criteria

### AC1: Constant to Enable Frame-Level Results
**Given** `run_cv.py` has a constant `SAVE_FRAME_LEVEL_RESULTS` defined at the top of the file
**When** the constant is set to `True`
**Then** `deeplabcut.evaluate_network()` is called with `save_frame_level_results=True`
**And** when the constant is `False`, `save_frame_level_results=False` is passed
**And** the constant is defined alongside other configuration constants like `N_EPOCHS`, `N_FOLDS`, etc.

### AC2: Parse Frame-Level CSV After Evaluation
**Given** `deeplabcut.evaluate_network()` has completed for a specific fold/seed/landmark_set  
**When** the frame-level CSV exists in the evaluation folder  
**Then** the CSV is read into a DataFrame  
**And** metadata columns (fold, seed, experiment_id, landmark_set_name, shuffle_num) are added

### AC3: Separate Aggregate Files Per Landmark Set
**Given** an experiment with landmark sets `{'all': 'all', 'truncated': [...]}` and experiment_id `'ll_0d025'`  
**When** frame-level results are aggregated  
**Then** two separate files are created:
- `cv_frame_level_results_ll_0d025_all.csv`
- `cv_frame_level_results_ll_0d025_truncated.csv`

### AC4: Incremental Appending
**Given** an aggregate file already exists with N rows  
**When** a new frame-level CSV with M rows is parsed and appended  
**Then** the aggregate file contains N+M rows  
**And** the new rows are appended to the end  
**And** the file is saved after each append (similar to `save_results_incrementally()`)

### AC5: Metadata Accuracy
**Given** fold_idx=2, seed_idx=1, experiment_id='test_exp', landmark_set_name='all', shuffle_num=107  
**When** frame-level results are parsed  
**Then** every row in the parsed DataFrame has:
- `fold` = 2
- `seed` = 1
- `experiment_id` = 'test_exp'
- `landmark_set_name` = 'all'
- `shuffle_num` = 107

### AC6: Handle Missing Frame-Level CSV
**Given** `deeplabcut.evaluate_network()` completes but no frame-level CSV is found  
**When** attempting to parse the frame-level results  
**Then** a warning is logged  
**And** execution continues without crashing  
**And** no rows are appended to the aggregate file

### AC7: Column Order Preservation
**Given** the original frame-level CSV has columns: `[frame_index, image_path, gt_nose_x, ...]`  
**When** metadata columns are added  
**Then** the aggregate CSV has columns: `[fold, seed, experiment_id, landmark_set_name, shuffle_num, frame_index, image_path, gt_nose_x, ...]`  
**And** metadata columns appear first

### AC8: Integration with Existing CV Workflow
**Given** `run_cv.py` is executing a 5-fold, 2-seed cross-validation with 2 landmark sets  
**When** all 10 fold/seed combinations complete  
**Then** each landmark set's aggregate file contains 10 × (test_set_size) rows  
**And** the main CV results file (`cv_results_{experiment_id}.csv`) is unaffected

## Technical Considerations

1. **File Location**: Aggregate files should be in the same directory as `cv_results_{experiment_id}.csv` (project root or working directory)

2. **CSV Parsing**: Use `pd.read_csv()` to read frame-level CSVs

3. **Incremental Saving**: Follow the pattern in `save_results_incrementally()`:
   ```python
   def save_frame_level_results_incrementally(results_df, results_file):
       results_df.to_csv(results_file, index=False)
       print(f"Frame-level results saved to: {results_file}")
   ```

4. **Error Handling**: Wrap CSV parsing in try-except to handle missing files gracefully

5. **Memory Efficiency**: Don't load the entire aggregate file into memory - just append new rows

6. **Compatibility**: Ensure this works with both PyTorch and TensorFlow backends (both generate the same CSV format)

## Out of Scope

- Aggregating summary metrics (already handled by existing CV results aggregation)
- Generating visualizations or plots from aggregate frame-level data
- Filtering or transforming frame-level data (just aggregate as-is)
- Resume/recovery logic for frame-level aggregation (if a fold fails, re-running will regenerate the data)
